# Logo Eraser

一个可以直接双击打开、完全在浏览器本地运行的视频去水印 / 去 Logo 工具。

## 运行

1. 双击 `index.html`。
2. 推荐使用最新版 Chrome 或 Edge。
3. 选择视频，按页面步骤操作。

不需要安装依赖、不需要启动本地服务器，也不会把视频上传到任何地方。所有第三方库都已内嵌在这个 HTML 文件里。

## 操作流程

1. **导入与拆帧**：浏览器本地解码视频，并按时间顺序保存所有分析帧。长视频会均匀跳帧以控制内存。
2. **逐帧框选参考帧**：参考帧按**固定间隔**从整段视频中抽取（默认 12 帧，可选 1–60 帧），一定包含第 0 帧和最后一帧。用画面左右两侧的 ← → 按钮（或直接点缩略图）切换参考帧，**为每一帧单独框选 Logo / 文字**，选区逐帧缓存，切回来还在。
3. **选择水印类型**：
   - 图形 / Logo：框选 Logo 本体。
   - 文字水印：框选文字，工具会分析笔画、颜色和局部对比度。
4. **定位轨迹**：
   - Logo 模式（自动）：按用户设置的间隔（默认每 6 帧）抽取关键帧，用**所有已框选参考帧合成**的边缘结构模板匹配找出每帧 Logo 的位置；低置信度结果会被剔除，其余位置用平滑曲线补间到每一帧。
   - Logo 模式（**手动轨迹**，推荐给会跳变/背景相似的素材）：勾选「手动标注轨迹」，拖动进度条到需要标记的时间点，在画面上点一下 Logo 中心即可记一个关键帧。两个关键帧之间按直线补间，范围外保持最近的关键帧；**框的大小始终等于参考帧选区**。可选的「局部细化」只在 ±16px 内用模板微调，绝不会跑离你标的位置。
   - 文字模式：默认使用**手动位置点**。在轨迹画面上点击文字中心，水印每次跳到新位置就补一个点；最新位置点一直使用到下一点，不做平滑或插值。也可关闭手动位置，使用实验性的逐帧自动检测。手动点只会做 ±4px 的严格微调，不会把你画的框拖走。
5. **修复**：
   - Logo 模式：按固定时间偏移（默认 36 帧，约 1.2 秒）选择 donor，并让 donor 随目标逐帧推进，避免同一帧被反复使用造成“冻结几帧再跳变”；只对 Logo 核心做空间修补，外圈 16px smootherstep 羽化。
   - 文字模式：把参考帧的笔画先验随当前位置平移/缩放，并对每帧做局部 NCC 对齐，修正点击误差和轻微尺寸变化；只擦除文字笔画及其一小圈软边，再用周围颜色的扩散 + 小块纹理填充。文字模式**不做跨帧 donor 还原**。
6. **导出**：重新编码为 MP4（H.264）或 WebM（VP9），并在浏览器支持时保留音轨。

### 多参考帧：为什么框得越多越准

- 每一帧的选区都会裁出一个模板，所有模板按相关度加权平均成一个"集成模板"。
- **先对齐再平均**：手画的框在帧与帧之间不可能像素一致，而模板是边缘图——实测框差 4px 就会让同一 Logo 的相关度从 0.70 掉到 0.17。所以每个参考帧会先用锚点模板在自己的框附近做一次滑窗对齐，再统一用锚点尺寸裁剪。不对齐的话，多参考帧会退化成"只有一帧"，甚至因为把错位模板平均而变糊——这就是"多参考帧反而不如单帧"的原因。
- 背景噪声在各帧之间互不相关，平均后幅度约降到 `1/√N`；水印结构在所有帧里一致，被保留下来。所以 12–20 帧的模板比单帧干净得多，弱水印也不容易被背景边缘抢走。
- 相关度太低的帧（框到的不是同一内容）会被自动排除，并在缩略图上标「偏差大」，不会污染模板。
- 参考帧越多，准备时间和内存占用越高；60 帧一般只在极难定位时使用。

### 模板预览微调

右侧「Logo 模板预览」会放大显示当前选区（含少量周边环境），可以直接在预览里拖四角改尺寸、拖内部平移；`1× / 2× / 4×` 调整预览的取景范围，`−W / +W / −H / +H` 做 1 像素步进。预览和主画面、数值输入三向同步。

### 文字水印模式

1. 在“水印类型”中选择「文字水印（逐帧擦除）」。
2. 在参考帧中框选文字（同样建议逐帧框选）。白色、半透明白字通常可直接使用自动颜色；深色字或特殊颜色可手动调整“文字颜色”。
3. 确认选区后进入轨迹页。默认勾选“手动位置”，滚动到轨迹画面，点击文字中心记录位置点。
4. 如果水印在视频中跳变、换行、改变大小，在每个新位置各点一次即可；位置点之间不会做补间。
5. 进入修复页预览。复杂/动态背景上，文字擦除后会留下局部平滑或纹理不一致的痕迹，这是信息缺失导致的近似填充。
6. 自动检测仅作为实验功能：低透明度、背景与文字颜色接近、前景遮挡时容易漏检或误检。

文字模式的关键实现：
- 用高通响应 + **相对背景的饱和度** + 局部亮度方向建立文字笔画先验，避免单纯用“接近白色”误伤彩色 UI，也避免固定阈值在高饱和背景上失效。
- 高通只标记边缘，所以还会把被笔画完全包围的封闭区域（字形内部、字母的封闭孔）补进先验，否则粗笔画擦完会留下亮块。
- 参考笔画先验会记录锚点和笔画特征；目标帧用局部多尺度 NCC 修正点击位置和轻微缩放。
- 只擦除先验笔画及 1–2px 软边，不把整个文字框当矩形补丁。
- 填充优先使用局部扩散，再在空洞较小时用 exemplar/PatchMatch 结果补充纹理（并与扩散结果做一致性守卫，避免凭空造出亮块）；也可选择“指定纯色”。
- 不做跨帧 donor 取回：相邻帧可能仍有同一水印，直接复制会重新带回文字。

## 历史记录

- 成功导出视频后，页面会把**文件信息、逐帧选区（含每个参考帧的框选）、逐帧轨迹和处理参数**记录到当前浏览器的 `localStorage`。
- **不会缓存原视频、视频帧或导出的成品文件**，所以历史记录只占用很少空间。
- 文字模式会保存手动位置点、文字颜色/容差和填充设置；恢复时重新拆帧并重建笔画 mask。
- 在顶部点击「历史」即可查看。点击「恢复处理」需要重新选择同一个原视频文件（浏览器安全限制不允许自动读取本地路径），选中后会自动拆帧、恢复轨迹，并回到修复导出页。
- 历史记录只保存在当前浏览器；清理浏览器站点数据会同时删除它们。

## 数据与调试

开发者控制台里可以直接查看两个核心数据：

```js
LogoEraserDebug.all_logo_rects
LogoEraserDebug.all_restore_logo_rects
```

- `all_logo_rects`：逐帧 Logo 位置、尺寸、来源（检测 / 插值 / 锚点）。
- `all_restore_logo_rects`：逐帧修复记录，包括窗口、跨帧来源和使用的干净像素量。

## 限制与建议

这是一个**单文件、零服务器、经典计算机视觉**实现，不是生成式 AI 去水印模型。

- **移动的 Logo 效果最好**：背景会随着 Logo 移动暴露出来，跨帧取回的像素能较完整地还原背景。
- **静止 Logo 更困难**：如果 Logo 固定不动，被它遮住的背景在整段视频里从未出现过，只能靠空间修补推测。16px 羽化能减弱明显的矩形硬边，但大面积、复杂纹理的静止 Logo 仍可能留下模糊或纹理不一致的痕迹。
- **背景运动**：跨帧取回假设相机/背景在相近位置基本一致。强烈运镜、背景中的人或物体移动可能造成接缝或残影。
- **动态背景（重要）**：如果背景本身在持续动画（动态壁纸、AI 动画、头发/水波/花瓣等），被 Logo 挡住的动画相位在源视频里并不存在。工具只能用前后约 1.2 秒的 donor 去补，播放时补丁内容可能与周围存在相位差；暂停看单帧正常、播放时仍能看出区域，属于这类信息缺失，不是羽化或调参能完全解决的。
- **长时间遮挡**：Logo 长时间停在同一区域时，固定偏移 donor 能提供的真实像素会变少，剩余核心会走空间修补，局部可能变软。
- **参考帧需要逐帧框选**：这是准确率的代价，工具不再自动猜测其余参考帧的位置。参考帧越多越准，但框选工作量也越大；如果水印在视频里几乎不动，4–8 帧就足够。
- **只支持矩形选区**：选区应尽量贴近 Logo。修复时会在四周额外扩展 20px，其中外圈 16px 用于与周围画面羽化融合。
- **固定尺寸跟踪**：默认 Logo 在视频中大小不变。Logo 发生缩放时可能需要重新选择参考帧。
- **文字位置点必须覆盖跳变**：文字模式不会猜测两次点击之间的轨迹。水印换了位置而用户没有补点，后续帧会按旧位置擦除，可能擦错或留下文字。
- **多段拼接素材要分段处理**：如果视频由多个片段拼成、每段水印位置不同（常见于广告合集），跟踪只有一条轨迹，跨片段的跳变会丢失目标。请分段处理，或在每个新位置补位置点，不要指望一次框选覆盖全片。
- **文字自动检测是实验功能**：低透明度、文字与背景颜色接近、文字被前景遮挡时可能漏检；当前建议默认使用手动位置点。
- **文字尺寸变化有范围**：局部对齐约在参考尺寸的 75%–125% 内搜索。文字明显放大/缩小时，建议重新选择参考帧或重新框选。
- **文字擦除不是生成式修复**：复杂或动态背景下，擦除区域可能留下局部平滑痕迹、纹理不一致或轻微色块；纯色/简单纹理背景效果更好。
- **文字模式不做跨帧取回**：相邻帧通常仍有水印，直接复制 donor 可能把文字带回来，因此只做空间填充。
- **选区别切到强边缘**：如果文字框把面板边框、字幕条、地平线这类高对比度边缘也框进去，擦除后的填充会把那条边缘的颜色抹开（例如紫色面板向上洇成一片渐变）。请把框贴紧文字、避开这些边缘；水印被 UI 压掉一半时，接受局部平滑痕迹。
- **多线程**：页面会通过 `navigator.hardwareConcurrency` 检测逻辑 CPU 核心数，并为每个逻辑核心启动一个 Worker（上限 32 个），并行处理拆帧编码、模板匹配和空间修补。文字模式的扩散/小块纹理填充在当前主线程执行。
- **长视频**：浏览器内存有限，单次最多分析 2400 帧；超出时会均匀跳帧并降低输出帧率。建议对长视频先剪辑出需要处理的部分。
- **导出依赖 WebCodecs**：Chrome/Edge 支持最好。MP4 的 H.264 音轨通常直接复制源文件 AAC 音轨；如果浏览器没有 AAC 编码器，可以改用 WebM 保留声音。
- **手机竖屏视频**：自动读取视频旋转元数据，修复后输出为正向画面。
- **历史记录不包含成品**：只记录参数与轨迹；重新处理时必须重新选择原视频，无法从历史中直接下载上一次导出的文件。

## 技术信息

- 解码：HTMLVideoElement 备用解码 + MP4Box.js 解析 MP4 + WebCodecs `VideoDecoder`
- 跟踪：多尺度灰度边缘图上的归一化互相关（NCC），模板由多个逐帧框选的参考帧加权集成，并做连续性过滤
- 文字定位：手动位置点 + 局部高通笔画先验 + 多尺度 NCC 位置/尺度微调（不做轨迹插值）
- 补间：PCHIP 单调三次插值（或线性，仅 Logo 模式）
- 修复：Logo 使用固定时间偏移的逐帧 donor 路径 + 核心区域内容感知块修补 + 16px 羽化融合；文字使用逐帧笔画 mask + 扩散填充 + 小型 exemplar/PatchMatch 纹理混合
- 多线程：`navigator.hardwareConcurrency` → Worker 池；拆帧编码 / 模板匹配 / 空间修补并行执行
- 导出：WebCodecs `VideoEncoder` + mp4-muxer / webm-muxer
- 音轨：AAC 原始样本直通复用，或 WebCodecs `AudioEncoder` 转码（AAC/Opus）
